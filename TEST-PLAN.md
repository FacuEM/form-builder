## Affected Pages/Routes

- `/forms/[id]` — Respondent form: question flow, animations, per-question API writes
- `/dashboard` — Creator forms list
- `/dashboard/forms/[id]/edit` — Builder: question creation, editing, reordering
- `/dashboard/forms/[id]/responses` — Responses dashboard: table + slide-over detail
- `/login`, `/signup` — Auth pages
- `/auth/callback` — Supabase code exchange
- `POST /api/forms/[id]/responses` — Unprotected respondent write endpoint
- `GET /api/forms/[id]/responses` — Protected creator read endpoint
- `GET/PATCH/DELETE /api/forms/[id]` — Form management

## Key Interactions to Verify

### Respondent flow
- Fill a short text question → Enter → advances to next question
- Fill a long text question (textarea) → Enter → advances
- Select a choice with keyboard shortcut (A/B/C) → Enter → advances
- Select from dropdown → auto-advances after 300ms
- Leave required question blank → Enter → shake animation, stays on question
- Back navigation → previous question slides in from left
- Forward navigation → next question slides in from right
- Complete final question → ThankYouScreen appears
- API call fails → inline error appears below input, can retry

### Builder flow
- Create new question → appears at bottom of QuestionList
- Edit question text (inline) → saved via Server Action
- Change question type TEXT → CHOICE → choices section appears
- Add choice → new choice input appears
- Remove choice → choice disappears
- Reorder: move question up/down with arrow buttons
- Publish toggle OFF → ON → shareable link appears
- Thank-you message editable in SettingsPanel

### Auth
- Unauthenticated request to `/dashboard` → redirected to `/login`
- Successful login → redirected to `/dashboard`
- Auth callback with valid code → session created

## Edge Cases

- `useRespondentState`: navigate back from first question → no-op (index stays 0)
- `useRespondentState`: `directionRef` freezes direction at navigate() call time, not read from state during exit animation
- `DropdownQuestion`: unmount before 300ms setTimeout fires → no state update on unmounted component
- `NavigationHint`: unmount before 800ms delay → clearTimeout fires, no opacity update
- `TextQuestion`: `type='LONG_TEXT'` renders `<textarea>` not `<input>`
- `POST /api/forms/[id]/responses`: `Form.published === false` → 403 (not 404)
- `POST /api/forms/[id]/responses`: unknown `responseId` in subsequent call → 404
- `POST /api/forms/[id]/responses`: same `respondentToken` + `formId` on retry → returns existing `responseId`, no duplicate Response row
- `GET /api/forms/[id]/responses`: session belongs to different creator → 403
- `DELETE /api/forms/[id]`: cascade deletes Questions, Choices, Responses, Answers
- `Answer` upsert: re-answering question updates existing Answer row (not insert new)
- `QuestionList`: first question — up button disabled; last question — down button disabled
- Server Actions: `revalidatePath` called after each mutation (builder UI reflects changes)
- `createForm` Server Action: `creatorId` populated from `supabase.auth.getUser()` — not hardcoded

## Critical Paths (E2E — Playwright)

1. **Full form submission**: Respondent loads published 4-question form (one of each type: TEXT, LONG_TEXT, CHOICE, DROPDOWN), answers all questions, reaches ThankYouScreen. Verify `Response.completed === true` in DB.

2. **Back navigation + re-answer**: Respondent answers question 1, advances to question 2, navigates back, changes answer to question 1, re-advances. Verify only one Answer row for that question (upsert worked).

3. **Creator end-to-end**: Creator signs up → creates form with 2 questions → publishes → shares `/forms/[id]` URL → respondent fills form → creator navigates to `/dashboard/forms/[id]/responses` → sees response in table → clicks row → ResponseDetail slide-over shows correct answers.

4. **Auth gate**: Unauthenticated request to `/dashboard/forms/[id]/edit` → redirect to `/login` → after login → redirect back to intended URL.

5. **Unpublished form**: Respondent loads `/forms/[id]` for an unpublished form → 404 page. POST to `/api/forms/[id]/responses` directly → 403.

6. **Error recovery**: Network error on question 1 POST → inline error shown → retry button → success → responseId stored → question 2 POST includes responseId.

## Notes for /qa and /qa-only

When running QA:
1. Start with the respondent flow — it's the north star interaction
2. Test all 4 question types in a single form (the 4-question golden-path form)
3. Pay special attention to animation direction: forward slides right→left, back slides left→right
4. Verify keyboard shortcuts work: A/B/C/D for choices, Enter to advance everywhere
5. Test on mobile: dropdown auto-advance should work with native picker; keyboard hints hidden on touch
6. Check "Press Enter ↵" hint: should appear at 800ms, disappear when next question loads
